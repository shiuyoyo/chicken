# 食品工廠 ERP

手機、電腦都能用的食品工廠整合系統（範例：雞肉調理包工廠 + 工廠直營門市）。
ERP、CRM、WMS、POS、品管、會計共用同一套資料，任何一張單據都能往前、往後追。

## 系統與關聯

| 系統 | 內容 | 與其他系統的關聯 |
| --- | --- | --- |
| **CRM 客戶關係** | 客戶 360、聯絡人、互動紀錄與待辦提醒、商機看板、報價單、價格表、回購預測、會員 | 報價單一鍵轉銷售訂單；價格表自動帶入訂單 |
| **銷售** | 銷售訂單、信用額度、最低售價、退貨 | 依配方算缺料 → 採購單；依訂單開工單；超過額度/低價送簽核 |
| **採購** | 採購單（金額門檻簽核）、進貨（可部分到貨、超收控管）、退回供應商 | 進貨建立原料批號、放到儲位、產生應付帳款 |
| **倉儲 WMS** | 多倉庫、儲位、溫層檢查、批號、先到期先出（FEFO）、調撥、盤點、效期預警、待處理區 | 領料、出貨、門市都從這裡扣庫存 |
| **生產** | 工單、排程（產線產能）、領料、投料、產出、結案退料、標準 vs 實際成本、良率 | 投料記錄原料批號 → 成品批號（追溯用） |
| **品管 QC** | 進料檢驗 IQC、成品抽檢 FQC、暫扣、報廢、不合格改判需主管核准 | 未合格的原料不能領用、成品不能出貨或送門市 |
| **出貨** | 揀貨單（FEFO、客戶效期要求）、箱數、貨櫃 / 車號、開立發票 | 出貨扣庫存、銷貨成本入帳、開立應收 |
| **門市 POS** | 收銀、會員點數、折扣權限、現金找零、作廢（店長）、日結對帳 | 只賣門市儲位有庫存的品項（由倉庫調撥補貨） |
| **會計** | 應收、應付、帳齡、收付款、費用、手動傳票、損益表、試算表、月結關帳 | 所有進出貨、生產、門市、退貨自動產生傳票 |
| **食品追溯** | 任一批號往上追原料與供應商，往下追客戶與門市會員，產出召回名單 | 串起採購、生產、出貨、POS |
| **訂單進度** | 接單 → 原料進貨 → 領料 → 投料 → 產出 → QC → 出貨 → 收款，每階段數量與完整歷程 | 彙整所有關聯單據 |
| **權限與簽核** | PIN 登入、角色權限矩陣（無 / 檢視 / 編輯 / 核准）、簽核中心、操作紀錄 | 套用在所有系統；申請人不能核准自己的申請 |
| **開發者** | 資料表瀏覽、外鍵完整性與帳務健康檢查、備份還原、Supabase 設定與建表 SQL | — |

「系統關聯圖」頁面有完整的資料流圖與 48 個資料表關聯。

## 營運規則（都有自動化測試）

- 採購單超過 5 萬、訂單超過客戶信用額度或低於最低售價、庫存調整 / 盤差超過 3 千、銷貨退回、POS 作廢、QC 改判 → 送簽核
- 冷凍品不能放常溫倉；未 QC 合格、已過期的批號不能領用或出貨；客戶要求的剩餘效期不足的批號不出
- 進貨超收 10%、領料超過配方 20%、出貨超過訂單、收款超過未收金額 → 擋下
- 任何動作中途失敗 → 整批還原，不留下半套資料
- 關帳後，關帳日以前的日期不能再新增任何帳務異動

## 兩種介面

- **標準模式**：選單 + 表單，給辦公室與年輕同仁。
- **大按鈕模式**（`#/simple`）：一排一個大框框（進貨／領料投料／生產產出／出貨／品管／門市收銀），
  數量可選「👆 點擊計數」或「⌨️ 直接輸入」，有包裝單位的可以直接用「箱」計。

## 開發與測試

```bash
npm install
npm run dev          # 開發（--host，同網段手機可直接連）
npm test             # 業務規則測試（vitest）
npm run build        # 產生 dist/
npm run build:single # 單一 HTML 檔 dist-single/index.html
npm run schema       # 由 src/db/schema.js 重新產生 supabase/schema.sql
npm run e2e          # 驗收測試（需先 npm run build && npm run preview）
```

## 資料庫

預設存在**瀏覽器本機**（每台裝置一份，第一次開啟載入示範資料）。
要讓多台裝置共用時改用 Supabase：

1. 建立 Supabase 專案，在 SQL Editor 執行 `supabase/schema.sql`
2. 在「開發者 → 資料庫設定」填入 Project URL 與 anon key，按「上傳本機資料並切換」
   （或在 `.env` 設定 `VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`）

> schema.sql 的 RLS policy 目前允許匿名讀寫，只適合試用。正式上線前要改用 Supabase Auth 登入並設定 policy；
> 目前的 PIN 登入與權限檢查在瀏覽器端執行，可防止誤操作，但不能防止懂技術的人繞過。

## 程式結構

```
src/db/schema.js    資料表與關聯定義（本機與 Supabase 共用）
src/db/store.js     讀寫中心：記憶體快取、交易還原、單號
src/db/seed.js      示範資料（用正式業務邏輯跑出來）
src/logic/          業務邏輯：core 權限/簽核/會計、inventory WMS、purchase、sales、production、
                    qc、shipping、pos、crm、accounting、trace 追溯、progress、reports、admin
src/pages/          標準模式各頁
src/simple/         大按鈕模式
src/pos/            門市收銀台
tests/              業務規則測試、驗收測試（tests/e2e）
```
