# 工廠 ERP

手機、電腦都能用的製造業整合系統。不限食品業：示範資料是雞肉調理包工廠 + 工廠直營門市，
但同一套流程也適用組裝業（零件 → 組件 → 成品）、禮盒組合等。
ERP、CRM、WMS、POS、品管、會計共用同一套資料，任何一張單據都能往前、往後追。

## 系統與關聯

| 系統 | 內容 | 與其他系統的關聯 |
| --- | --- | --- |
| **品項與 BOM** | 原料、包材 / 零件、半成品、成品；多階 BOM（半成品、成品都能當零件，例如醬汁 → 調理包 → 禮盒）、迴圈檢查、多階展開、用途查詢（用在哪裡）、多階標準成本；變化款（同一款不同口味 / 顏色 / 尺寸各自一個料號）；分類、效期規則、檢驗範本、是否需要 QC | 訂單依多階 BOM 算缺料、開工單 |
| **CRM 客戶關係** | 客戶 360、聯絡人、互動紀錄與待辦提醒、商機看板、報價單、價格表、回購預測、會員 | 報價單一鍵轉銷售訂單；價格表自動帶入訂單 |
| **銷售** | 銷售訂單、信用額度、最低售價、退貨 | 依多階 BOM 算缺料（半成品先扣庫存）→ 採購單；依訂單開工單（不夠的半成品 / 組件先開工單）；超過額度/低價送簽核 |
| **採購** | 請購單（轉採購單、依安全庫存自動產生）、採購單（金額門檻簽核）、進貨（可部分到貨、超收控管）、退回供應商 | 進貨建立原料批號、放到儲位、產生應付帳款 |
| **倉儲 WMS** | 多倉庫、儲位、溫層檢查、批號、先到期先出（FEFO）、調撥、盤點、效期預警、待處理區 | 領料、出貨、門市都從這裡扣庫存 |
| **生產** | 成品與半成品工單、排程（產線產能）、領料、投料、產出、結案退料、標準 vs 實際成本、良率 | 投料記錄用料批號 → 產出批號（追溯用）；組裝品效期取最早到期的組件 |
| **品管 QC** | 進料檢驗 IQC、成品 / 半成品抽檢 FQC、檢驗範本（食品、組裝、零件…可自訂）、暫扣、報廢、不合格改判需主管核准 | 未合格的原料不能領用、成品不能出貨或送門市 |
| **出貨** | 揀貨單（FEFO、客戶效期要求）、箱數、貨櫃 / 車號、開立發票 | 出貨扣庫存、銷貨成本入帳、開立應收 |
| **門市 POS** | 收銀、掃描槍、會員點數、折扣權限、現金找零、作廢（店長）、日結對帳、電子發票證明聯（買方統編）；展場多台平板：收銀機代號、每班保留發票號碼區段、斷網照常結帳、恢復網路自動上傳 | 只賣門市儲位有庫存的品項（由倉庫調撥補貨） |
| **促銷與業績** | 促銷活動依日期自動套用活動價（批發 / 門市）；業務業績：銷售額、目標達成率、毛利、接單、新客戶、報價成交 | 活動價不算低於最低售價（伺服器也認得）；業績依訂單上的業務歸屬 |
| **掃碼銷貨** | 掃描槍嗶商品，一次產生訂單、出貨單（銷貨單）、應收與發票 | 依先到期先出扣庫存；超過信用額度會先送簽核 |
| **會計** | 應收、應付、帳齡、收付款、費用、手動傳票、損益表、試算表、月結關帳 | 所有進出貨、生產、門市、退貨自動產生傳票 |
| **批號追溯** | 任一批號多階往上追到每一層用料與供應商，往下追到半成品、成品、禮盒，再到客戶與門市會員，產出召回名單 | 串起採購、生產、出貨、POS |
| **訂單進度** | 接單 → 原料進貨 → 領料 → 投料 → 產出 → QC → 出貨 → 收款，每階段數量與完整歷程 | 彙整所有關聯單據 |
| **LINE / Telegram 通知** | 員工加入官方帳號自己選職位，管理員在後台確定後，相關資料異動自動推播（簽核、訂單、進貨、工單、QC、出貨、收款、低庫存、日結、關帳）；可設定每種事件通知哪些職位；網頁上有模擬器可以試用 | 通知在每個業務動作的同一個交易中產生；設定方式見 [docs/line-setup.md](docs/line-setup.md) |
| **表單列印** | 簽核單、BOM 表、報價、訂單、出貨、揀貨、請購、採購、進貨、領料、退料、生產入庫、製令、生產日報、檢驗、對帳單、傳票、帳齡表、試算表、損益表、庫存明細、效期預警、價目表、主檔清單；批號標籤與出貨嘜頭（QR Code）、58mm 收據。清單見 [docs/forms-checklist.md](docs/forms-checklist.md) | 每筆庫存異動都有單號（RC 進貨、MI 領料、MR 退料、MS 入庫…），對應鼎新的單據 |
| **權限與簽核** | PIN 登入、角色權限矩陣（無 / 檢視 / 編輯 / 核准）、簽核中心、操作紀錄 | 套用在所有系統；申請人不能核准自己的申請 |
| **開發者** | 資料表瀏覽、外鍵完整性與帳務健康檢查、備份還原、Supabase 設定與建表 SQL | — |

「系統關聯圖」頁面有完整的資料流圖與資料表關聯。與鼎新 ERP 的流程對照見 [docs/digiwin-comparison.md](docs/digiwin-comparison.md)。操作說明見 [docs/manual.md](docs/manual.md)；掃描槍、發票機、點陣印表機、展場平板的設定見 [docs/hardware.md](docs/hardware.md)。

## 營運規則（都有自動化測試）

- 採購單超過 5 萬、訂單超過客戶信用額度或低於最低售價、庫存調整 / 盤差超過 3 千、銷貨退回、POS 作廢、QC 改判 → 送簽核
- BOM 不能形成迴圈（A 用到 B、B 又用到 A）；同系列的變化款選項不能重複
- 冷凍品不能放常溫倉（溫層選填，不需要溫控的品項不檢查）；未 QC 合格、已過期的批號不能領用或出貨；客戶要求的剩餘效期不足的批號不出
- 進貨超收 10%、領料超過 BOM 20%、出貨超過訂單、收款超過未收金額 → 擋下
- 任何動作中途失敗 → 整批還原，不留下半套資料
- 關帳後，關帳日以前的日期不能再新增任何帳務異動

## 兩種介面

- **標準模式**：選單 + 表單，給辦公室與年輕同仁。
- **大按鈕模式**（`#/simple`）：一排一個大框框（進貨／領料投料／生產產出／出貨／品管／門市收銀），
  數量可選「👆 點擊計數」或「⌨️ 直接輸入」，有包裝單位的可以直接用「箱」計。

## 開發與測試

```bash
npm install
npm run dev          # 開發（--host，同網段手機可直接連）
npm test             # 業務規則測試 + 資料庫權限測試（vitest；有安裝 PostgreSQL 才會跑權限測試）
npm run build        # 產生 dist/
npm run build:single # 單一 HTML 檔 dist-single/index.html
npm run schema       # 由 src/db/schema.js 重新產生 supabase/schema.sql
npm run e2e          # 驗收測試（需先 npm run build && npm run preview）
npm run e2e:cloud    # 雲端版驗收：Email 登入、開通、權限（需要本機 PostgreSQL，會自己建置與啟動）
npm run e2e:flows    # 全流程驗收（本機版，需先 preview）；npm run e2e:flows:cloud 跑雲端版
npm run test:replay  # 業務規則測試的每一批寫入都送進真的 PostgreSQL，確認伺服器不會擋正常操作
npm run test:functions # Edge Functions 測試（需要 Deno）
```

## 資料庫與上線

預設存在**瀏覽器本機**（每台裝置一份，第一次開啟載入示範資料，用 PIN 登入）。

要讓多台裝置共用、正式上線時改用 **Supabase + Vercel**，步驟見 [docs/deploy.md](docs/deploy.md)：

- 員工用 **Email + 密碼** 登入（Supabase Auth，要驗證信箱）；管理員在「使用者與權限」登記員工的 Email 才算開通。
- 資料庫依登入者的角色檢查讀寫（Row Level Security），傳票平衡、關帳、庫存不足、簽核規則也在伺服器端再檢查一次。
  一個動作的所有異動在同一個資料庫交易裡完成，有一筆被拒絕就整批取消。
- 簽核門檻（採購金額、信用額度、最低售價、調整 / 盤差金額、退貨、作廢、QC 改判）與數量上限（超收、超領、超出貨、超額收付款）也由伺服器檢查，見 [docs/deploy.md 的安全性一節](docs/deploy.md#安全性伺服器上檢查了什麼)。

## 程式結構

```
src/db/schema.js    資料表與關聯定義（本機與 Supabase 共用）
src/db/policies.js  雲端權限規則與伺服器端檢查（產生在 supabase/schema.sql）
src/cloud/          雲端版登入、開通、第一次設定畫面
src/db/store.js     讀寫中心：記憶體快取、交易還原、單號
src/db/seed.js      示範資料（用正式業務邏輯跑出來）
src/logic/          業務邏輯：core 權限/簽核/會計、bom 多階 BOM/變化款/檢驗範本、inventory WMS、purchase、sales、production、
                    qc、shipping、pos、crm、accounting、trace 追溯、progress、reports、admin
src/pages/          標準模式各頁
src/simple/         大按鈕模式
src/pos/            門市收銀台
tests/              業務規則測試、驗收測試（tests/e2e）
supabase/functions/ LINE / Telegram webhook 與通知發送（Supabase Edge Functions）
```
